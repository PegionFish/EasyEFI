# S15 交接（引导脚本与启动链）

## 交付清单
- boot/startup.nsh — 严格布局生产脚本（两 ESP 逐字节相同；%homefilesystem% 绝对路径 load）
- boot/startup-x64.nsh / startup-aa64.nsh — 兼容布局架构脚本（嵌套 Shell 相对路径；驱动由 trampoline 预加载）
- boot/ShellRunner/ — 兼容布局架构分流 trampoline（双架构同源码，卷枚举方案）
- boot/test-noautorun — 测试标志文件
- tests/expect/s15-*.txt — 冒烟断言
- scripts/build-shell.sh 归 S17；mktestimage --extra-file 扩展（leader 提交）

## 实证发现（已固化到 design.md §3.4 与代码注释）
1. **脚本内启动异架构 .efi 失败会中止 .nsh**（"Script Error Status: Unsupported"）——与 load 失败不中止不同；try-both 脚本方案作废，架构分流改在 UEFI 层（ShellRunner）。
2. **短格式 USB 引导展开时 LoadedImage->FilePath 可能无 FILEPATH 节点**——trampoline 不能做自身设备路径前缀手术，改卷枚举 + FileDevicePath。
3. **Shell LoadOptions 首 token 被当镜像名跳过**——必须 L"shell.efi <script>" 前缀；LoadOptions 经 LoadedImage 协议设置（gBS->LoadImage 无此参数）。
4. **嵌套 Shell（file-name 模式）不设置 %homefilesystem%**——架构脚本用相对路径；load 裸相对路径失败（S14 定位：EfiShellOpenFileList 要求 GetCurDir 非空）→ 驱动由 trampoline 预加载（LoadImage+StartImage+ConnectController）。
5. **Shell echo 把独立 `-` token 当 flag**——文案用分号不用破折号。
6. ArmVirtQemu 有内置 Shell（Boot0002 "EFI Internal Shell"）作回退——trampoline 失败时落入内置 Shell（非设计路径，失败模式可接受）；固件先试 BOOTX64 再 BOOTAA64，异架构 trampoline 被拒一行噪音属预期。
7. .nsh 注释符是 #（rem 报 unknown command，不中止但噪音）。
