## 契约符合性

**无变更**（`Include/Contract/**` 零改动；leader 的 VolFree 所有权裁决 main 332553a
已在本流实现落实：Fs 按卷缓存、指针跨调用稳定、VolFree 只释放数组+Dp、调用方借用）。

契约解释记录（不改头文件，仅实现选择）：
1. **Open 不截断**已有文件（对齐 MockFs 与 UEFI FAT 原生语义）。覆盖更短文件需
   Delete+Open(CREATE)——**S13 Editor 保存路径必须注意**（见集成注意事项）。
2. **Enum 不存在目录 → EFI_NOT_FOUND**（MockFs 平面表返回空集成功，系 mock 简化；
   真实 FS/UEFI 后端一致返回 NOT_FOUND，有意差异）。
3. **Info.Name = 规范化输入路径**（对齐 MockFs）；Enum 条目 Name = 基名。
4. **IsP3 = 同盘 + 分区3 + 标记**（`.easyefi` 或 `launcher.json`，§5.2 步骤 3 的"或"
   统一应用于步骤 2–4；兜底多命中确定性取一：启动盘优先，再按卷集顺序——
   "列候选让用户选"属 UI 职责，契约返回单个 Fs）。
5. **排序**：IsP3 优先，其余按设备路径字节序升序（稳定；契约未指定，实现选择）。
6. **跨目录 rename → EFI_UNSUPPORTED**（FAT SetInfo 改名相对父目录；FM F6 为同目录）。
7. `GPT_NODE_INFO.DiskSignature` 契约注释称 DiskGUID，但 UEFI HD(GPT) 节点 Signature
   实为 UniquePartitionGUID（Spec 2.10 §10.3.1）；S09 不消费该字段，仅提示 S05/S18 留意。

## 已知限制

1. **FsName 为启发式**（显示用途）：PartitionInfo GPT 类型 GUID → ESP="FAT32"、
   Microsoft Basic Data="NTFS"、其余="UNKNOWN"。Basic Data 分区理论上可为其它 FS；
   本镜像布局下即 NTFS。无 PartitionInfo 的卷（虚拟介质等）→ "UNKNOWN"。
2. **卷缓存只增不删**（会话级）：介质移除后缓存 Fs 不失效（句柄消失→枚举不再列出；
   旧借用仍指向旧实例，操作会失败但不会崩溃）。MVP 可接受；热插拔失效策略见建议。
3. **POSIX 后端符号链接按 stat 跟随**（不特殊处理）；超长路径（>NAME_MAX）由 OS 拒绝。
4. **CHAR16 按 UTF-16 码元处理**（代理对 ↔ 4 字节 UTF-8）；孤立代理 → EFI_INVALID_PARAMETER。
5. UEFI 后端 Enum/Info 的 Mtime 来自 EFI_TIME 转换（1970 前/无效 → 0）。
6. 冒烟 ntfs 镜像为 192M 小卷（S16 大容量/扩容场景不在本流）。

## 集成注意事项（给 leader）

1. **S11/S12/S13 所有权纪律（契约裁决已落实）**：`VolEnumerate`/`VolFindP3` 返回的
   `FS_OPS*` 均为**借用**，跨调用指针稳定（同 SFS 句柄同实例），**不得 Destroy**；
   `VolFree` 只释放数组与 Dp。宿主测试用 `FsPosixBackend(root)` 自建实例，由测试自行 Destroy。
2. **S13 Editor 保存**：FsOps Open 不截断。保存更短文件必须先 `Delete` 再
   `Open(WRITE|CREATE)`（或未来契约增加 truncate——见建议）。直接覆盖写会残留旧尾部。
3. **S11 Launcher**：`VolFindP3(BootDp, BootLen, &P3Fs)` 的 BootDp 传自身 LoadedImage
   **完整**设备路径（`VolOwnBootDp` 内部助手可复用：DeviceHandle dp + FilePath 拼接；
   单用 FilePath 只是文件段，无 HD 节点，匹配必失败——本流实证踩坑）。BootDp=NULL
   时 VolFindP3 自动取 gImageHandle 的完整路径。失败 EFI_NOT_FOUND → DEGRADED。
4. **S10 ExecAutoCandidates**：候选 Fs 同样借用卷缓存（裁决背景即此悬空崩溃）；
   排除启动盘用 `VolSameDisk`（前缀逐字节，克隆盘不误判）。
5. **驱动怪癖已适配（消费方无需再处理）**：FatOpenEx 仅接受 READ/READ|WRITE/READ|WRITE|CREATE；
   FatDelete 拒绝 READ-only 句柄（uDelete 以 READ|WRITE 打开）；edk2-stable202608
   警告码不带 MAX_BIT（`EFI_ERROR(EFI_WARN_DELETE_FAILURE)==FALSE`，uDelete 显式转
   EFI_DEVICE_ERROR）；Delete 无论成败都关闭句柄（不可再 Close）；EfiFs GetInfo 尺寸
   协商非标准（S14 已知限制 2，UefiGetInfoRobust 非零起始+有界重试）；**EfiFs SetInfo
   改名仅认卷根绝对路径**（基名静默忽略返回 SUCCESS——uRename 基名→验证→绝对路径
   重试→再验证，FAT/EfiFs 双兼容，未生效报 EFI_DEVICE_ERROR）。
6. **mktestimage ntfs 变体两处与本流冒烟不兼容**（leader 独占脚本，未改）：
   数据分区为 P2（非 P3，VolIsP3 分区号判定不命中，只能靠兜底）；默认 startup 裸相对
   `load` 路径有 S14 已报告 bug。本流自带严格三分区镜像脚本绕开；建议 leader 修正
   mktestimage-inner 或通知各 ntfs 使用方自带 startup/镜像。
7. **EfiMem ASSERT bug**（main 84c6f4c 引入，应用构建才暴露）已报 leader 并在 main 修复；
   本流临时 wrapper 已移除，全局解析恢复。
8. 冒烟应用 `SmokeS09.inf` 在本流 module.dsc.inc 的 [Components] 中，平台全量构建会
   一并构建（45KB，无副作用）；S18 集成镜像无需包含它。
9. 宿主测试二进制/dSYM 不入库（tests/.gitignore；leader 已在根 .gitignore 加 *.dSYM/）。

## 超范围建议（可选，leader 裁决）

1. **FsOps 增加 truncate 语义**（契约变更提案，未实施）：`FsOpen` 增加 FS_MODE_TRUNC
   或新增 `FsTruncate(Fs, H, Len)`。Editor 保存更短文件目前需 Delete+重建（有竞态窗口：
   删除后创建前掉电丢文件）；UEFI 侧可经 SetInfo(FileSize) 实现（FAT/EfiFs 均支持）。
   影响流：S09/S13。MVP 内 Delete+重建可用，故未擅自实施。
2. **卷缓存失效策略**：介质移除/`map -r` 后按句柄存活校验清理缓存（需先确认无借用，
   或引用计数）。MVP 会话级只增不删已满足安全（不悬空），热插拔体验优化留后续。
3. **mktestimage ntfs 变体改为严格三分区**（P3=分区3），与 design §3.1 一致，
   使各流 ntfs 冒烟天然覆盖分区号判定（leader 独占脚本）。
