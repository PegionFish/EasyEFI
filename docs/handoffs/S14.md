## 已知限制

1. **冒烟只证卷可见**（OpenVolume 成功 + 卷标签可读 + FS 映射出现）。任务书原 S14 验证项
   "写文件→重启→读回一致" 与 "最后句柄关闭后拔盘无挂死" 按 leader 派单范围归 S09/S18
   集成验证（上游 README 声明最后句柄关闭即完整卸载，防意外拔盘）。
2. **驱动 GetInfo(卷标签) 行为非标准**（上游代码如此，未补丁）：
   - NULL/0 尺寸缓冲问尺寸 → 返回 EFI_BUFFER_TOO_SMALL 但**不回写所需尺寸**；
   - 缓冲大于所需 → 也返回 EFI_BUFFER_TOO_SMALL，但回写精确尺寸；仅缓冲恰好等于所需时成功。
   - 消费者必须用**标准两阶段重试**（起始非零缓冲 → TOO_SMALL 时按回传尺寸重试），
     探针已按此实现。S09 FsOps 的 Info/卷标签查询务必沿用（见集成注意事项）。
3. RELEASE 构建 DebugLib 为 Null，驱动无 DEBUG 输出；排障需 DEBUG 变体（改 `-b DEBUG`，
   上游 DSC 已支持，未交付）。
4. 冒烟镜像 P3 为 mktestimage 默认 192M 小卷（TOOLKIT 标签 + `.easyefi` 标记），
   非真实容量场景；大容量/扩容归 S16。

## 集成注意事项（给 leader）

1. **S15 引导脚本必须用 `load %homefilesystem%\EFI\Drivers\ntfs.efi`**（design §3.3 形式）。
   实证：裸相对路径 `load EFI\Drivers\ntfs.efi` 报 "File not found"——Shell `load` 经
   `ShellOpenFileMetaArg` 解析相对路径失败（文件确在 ESP，mtools 核验）；应用执行
   （`EFI\Apps\x.efi`）的相对路径却可用，二者路径解析机制不同。
   **S00 `mktestimage-inner.sh` 默认 ntfs startup.nsh 即裸相对路径，存在此潜在 bug**
   （leader 独占脚本，S14 未改，冒烟经 `--startup` 覆盖绕开）——建议 leader 修正默认脚本
   或通知各 ntfs 变体使用方自带 startup。
2. **S09 FsOps**：卷标签/GetInfo 类查询用两阶段重试（起始缓冲 ≥256B，勿用 NULL 问尺寸），
   见"已知限制 2"。NTFS 卷可见性已由本流双架构实证，S09 可直接在 ntfs 变体镜像上开发。
3. **S16 打包**：`out/ntfs_x64.efi` → P1 `EFI/Drivers/ntfs.efi`，`out/ntfs_aa64.efi` → P2
   同名（架构中性文件名，design §3.1）；SHA256SUMS 可直接并入发布清单。
4. **基座镜像建议**：`docker/Dockerfile` 增加 `libc6-dev-amd64-cross`。ntfs-3g `types.h`
   直接 `#include <stdint.h>`，X64 交叉编译需目标架构 libc 头；现镜像
   `--no-install-recommends` 未含该包，`build-ntfs3g.sh` 目前在临时容器内按需 apt 补装
   （不改共享镜像，每次 X64 构建多 ~20s）。AA64 在 arm64 容器内即原生目标，无此问题。
5. 冒烟运行器依赖主仓库 Shell.efi（`/Users/bob/EasyEFI/Build/Shell/RELEASE_GCC/<ARCH>/...`，
   `SHELL_BUILD` 环境变量可覆盖）；S17 固化 Shell 后建议改指 S17 产物。
6. 驱动名内嵌版本宏 `DRIVER_VERSION=1.3 COMMIT_INFO=0964af8`（Shell `dh -v` 可溯源）。
