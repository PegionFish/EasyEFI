## 已知限制（实现语义，供消费流对齐）

1. **PartTypeGuid 恒为零**：HARDDRIVE_DEVICE_PATH 节点不携带分区类型 GUID，契约结构该字段无法从设备路径推导。需要类型 GUID 的调用方须自行读 GPT 分区表。
2. **首个 HD 节点决定 DpFindGpt**：GPT→成功；MBR→立即 EFI_UNSUPPORTED（不跳过 MBR 去找后续 GPT）；畸形→EFI_INVALID_PARAMETER；无 HD→EFI_NOT_FOUND。
3. **HD 节点 Length 必须恰为 42**（spec 固定结构尺寸）；GPT 格式要求 SignatureType==0x02；Size==0 或 Start+Size 溢出→EFI_INVALID_PARAMETER。
4. **仅考虑首个设备路径实例**：walker 遇 END_INSTANCE/END_ENTIRE 即停（END 节点本身不计入前缀）。
5. **无 HD 的合法缓冲**→前缀=整个已遍历跨度（整盘身份）；两个空前缀路径 VolSameDisk→TRUE。
6. **PartNumber=0 接受**（spec：0=整盘），但永不判为 P3。
7. 布尔 API（VolIsP3/VolSameDisk）对任何畸形/NULL/空输入返回 FALSE（fail-safe，绝不崩溃、绝不误判 TRUE）。

## 集成注意事项（给 leader）

1. **⚠ 派单简报规格笔误（需更正任务书）**：简报写 `MEDIA_DEVICE_PATH=0x01`，**实际 UEFI Spec 2.10 / edk2 为 `0x04`**（0x01 是 HARDWARE_DEVICE_PATH）。已对照 `~/.cache/easyefi/edk2/MdePkg/Include/Protocol/DevicePath.h` 核实并按真实 spec 实现（HD 子类型 0x01、42 字节、MBRType@40、SignatureType@41 均正确）。**S09/S10 构造合成设备路径时媒体/HD 节点 Type 必须用 0x04**，否则会把 PCI 节点误判为 HD。建议 leader 更正任务书 S05 输入节并通知 S09/S10。
2. **内存约定**：DpDiskPrefix callee 分配，成功时 `*Prefix` **恒非 NULL**（即使 `*PrefixLen==0` 也分配 1 字节），caller 经 MemFree 释放；失败时输出重置为 NULL/0。VolSameDisk/VolIsP3 内部自分配自释放，调用方无需管理。
3. **P3 发现（S09，design §5.2）**：VolIsP3 要求启动路径含 GPT HD 节点（步骤 1 锚定启动盘身份）；MBR 启动→FALSE→Launcher 降级 DEGRADED。同盘匹配走控制器前缀逐字节相等，不依赖签名 alone。
4. **auto: 排除（S10，design §5.6 / F03）**：用 `VolSameDisk(BootDp, VolDp)` 排除启动盘**全部分区**；克隆盘（同 DiskGUID、不同控制器路径）正确**不**被排除（仍可作外部候选）。
5. **聚合器**：module.dsc.inc 无需改动，EasyEfiPkg.dsc 已 !include 本碎片；.inf BASE_NAME/LIBRARY_CLASS/FILE_GUID 不变，消费流链接名不变。stub 已删除，S09/S10 集成时直接链接真实库。
6. 本流不碰真实固件、不做卷枚举/文件 I/O（S09 职责）；不处理 MBR 启动（范围外）。
