## 已知限制

1. **右下角格 (Rows-1, Cols-1) 永不输出到 ConOut**。edk2-stable202608 GraphicsConsoleDxe
   实证：画到行末（CursorColumn≥MaxColumn）立即内部输出 CRLF，底行遇 LF 整屏上滚，
   右下角格画出即被滚走且无法稳定恢复。故 Flush 跳过该格输出（清脏、保留缓冲值），
   屏幕保留清屏空格。**控件布局勿依赖该格**（S08 画框若铺满全屏，右下角 '+' 不显示）。
   缓冲快照含该格写入值，虚拟屏幕该格为空格——T06-4/T06-6 已按此断言。
2. **OVMF x64 ConSplitter 模式宽度虚高**：QueryMode 报告 100x31，但图形控制台实际仅
   可寻址列 0..97（SetCursorPosition(98/99,·) 返回 EFI_UNSUPPORTED）。TuiInit 遂对候选
   模式做右下角可寻址性探测并降级，x64 落回 80x25（保底）。aa64（serial-only）无此问题，
   取 80x50。此为固件 quirks，探测逻辑保证缓冲==屏幕、Flush 不报错。
3. Flush 后光标停靠 (0,0) 且可见（契约无光标隐藏 API）；输入行光标定位由上层另行 SetCursorPosition。
4. **EfiCompatShim 为临时件**（见集成注意事项），非长期设计。

## 集成注意事项（给 leader）

1. **S00 EfiMem.c 阻塞 bug（已单独报 leader，leader 独占文件未动）**：
   `MemRealloc` 调 `ReallocatePool(Ptr,0,NewSize)`，而 edk2 签名为 `(OldSize,NewSize,OldBuffer)`
   → 参数 1/3 类型互换，`-Werror` 下**任何链接 EfiCompatLib 的可执行模块都编不过**。
   S00 未暴露因应用 stub 未依赖 EfiCompatLib，且 `-m` 库构建不编译库依赖。
   即使修正参数序为 `(0,NewSize,Ptr)`，OldSize=0 仍会丢内容（与宿主 realloc 语义不符），
   正确修法需记录分配尺寸。**S11/S12/S13 链接 TuiScreenLib 前请先修 EfiMem.c。**
   本流绕行：`EfiCompatShim/`（修正版 EfiCompatLib 实例，尺寸头部 realloc）仅经碎片对
   `TuiScreenSmoke.inf` 作用域覆盖，不影响其它组件。**上游修复后请通知本流删除 shim 与覆盖。**
2. `TuiScreenLib.inf` `MODULE_TYPE` 由 BASE 升为 UEFI_DRIVER（依赖 UefiBootServicesTableLib 所需）；
   BASE_NAME/LIBRARY_CLASS 不变，消费方（UEFI_APPLICATION/UEFI_DRIVER/DXE_DRIVER）不受影响。
3. 后端注入为**链接期** `TuiScreenBackend()`：UEFI=TuiScreenUefi.c，宿主测试=tests/MockConOut.c。
   应用 core 宿主测试仍用框架 `tests/host/mocks/MockTui.c`（与本 lib 无耦合）。
4. 模式选择返回“最大完全可寻址”模式，`TuiGetSize` 给出实际尺寸；消费方按 GetSize 布局，
   勿硬编码 80x25（x64/aa64 实测尺寸不同）。
5. 冒烟复跑：`mktestimage.sh --arch <X64|AARCH64> --variant fat --shell <Shell.efi>
   --app S06Smoke=<TuiScreenSmoke.efi>` → `qemu-run.sh --expect SmokeApp/expect-smoke.txt`。
   Shell 二进制取主仓 `Build/Shell/RELEASE_GCC/<arch>/…/Shell/OUTPUT/Shell.efi`。
