## 已知限制（设计决策与约定）

1. **core 不依赖 S08 控件**：菜单/确认/帮助/错误页渲染在 core 内（编号/架构灰显/danger 标记/desc 展开属业务语义，TuiWidget 契约明确不管业务）。缩短关键路径；S12/S13 仍可用控件。
2. **core 借用 CONFIG**：glue 持有 ConfigFree/ConfigFreeErrors 生命周期；Reload 回调内 glue 原地更新 LAUNCHER_SESSION（含 P3Fs/映射名/Banner/Errs）。core 不链接 S03 符号 → 宿主测试直接构造 CONFIG 夹具。T11-5 的"坏 JSON"在 core 层以 cfg=NULL+Banner 覆盖；真实 JSON 解析链路由 S03/T03 + 冒烟覆盖。
3. **ExecOps 路径约定（需 S10 对齐，见集成注意事项 2）**：ExecEfi/ExecNsh 的 FullPath 一律 Shell 全限定 `fsN:/...`（glue 经 Shell->GetMapFromDevicePath 取启动 ESP 与 P3 映射名）；Fs 参数=所属卷（P3Fs/candidate->Fs/BootFs），显式 fsN: 项 Fs=NULL。
4. auto: 多命中 → CANDIDATES 选择态（Display 展示，options 保留）；单命中直接执行；零命中 → 错误页。候选 FullPath 直接用 S10 产出（契约已注明全限定）。
5. boot:XXXX → 直接 ExecBootNext（§5.6 无确认要求）；reset 动作与内置 Reboot → 强制 CONFIRM 默认 N；danger/confirm 标志 → CONFIRM。
6. 数字直选 1-9（单位）；导航端点钳制不环绕、跳过灰显；PgUp/PgDn 按视口行数。>9 条目用方向键。
7. options UTF-8→UCS-2 为 core 内静态严格解码器（非法字节/星面 → '?'；避免跨流依赖 Utf8Lib——集成后可选切换）。
8. `LAUNCHER_CONFIG_MAX_BYTES=65536` 模块常量（建议 PCD 化，见超范围建议）。
9. Count==0（无有效条目）→ 内置菜单 + 横幅（S03 交接约定）。
10. 无 Shell 协议（固件直启）→ 映射名空 → .nsh/apps/fsN: 执行报错页降级，菜单/Shell 退出仍可用；EASYEFI_RAN 仅在 Shell 可用时置（§3.4 语义）。
11. 倒计时由 glue 驱动（10×100ms PollKey+Stall=1s/Tick）；core Tick 纯逻辑可测。skip_timeout 生效值 glue 计算（cfg?cfg->SkipTimeout:PcdSkipTimeoutDefault）。
12. DEGRADED 且配置有效时：菜单=配置项（data: 灰显）+系统项；discovery 行仅在 cfg=NULL 时添加（配置自带 auto: 项即§5.2"auto: 外部介质条目"）。

1. **合并阻塞（UEFI 链接+冒烟）**：main 上 S06/S09/S10 仍为 probe-only stub。X64 链接实测缺符号：

   - S09 ExecVolumeLib：VolEnumerate/VolFindP3/VolFree
   - S10 ExecImageLib：ExecEfi/ExecNsh/ExecBootNext/ExecReset/ExecAutoCandidates/ExecFreeCandidates
   其余全部链接通过（S03/S04/S05/S07/JsonLib/EfiCompat）。**三流合并后通知我，我 rebase 跑双架构构建+6 场景冒烟**（预计无需改码；若 S10 路径约定不符见下条）。
2. **[需 S10 对齐] ExecOps 路径约定**：本流按"FullPath 全限定 fsN:/... + Fs=所属卷（显式 fsN: 为 NULL）"实现（契约 EXEC_CANDIDATE.FullPath"运行时全限定"与此一致）。S10 的 ExecEfi 需支持：Fs!=NULL 时可用 Fs 定位卷（或直接解析 FullPath 前缀）；Fs==NULL 时按 fsN: 前缀经 Shell 映射/句柄枚举定位。ExecNsh 两路径均全限定（ShellFullPath=启动 ESP 的 EFI/BOOT/BOOT{arch}.EFI，ScriptFullPath=脚本所在卷全限定）。S15 实证"LoadOptions 需 Argv0 前缀"归 S10 ExecNsh 内部构造。
3. **S06 渲染假设**：core 每状态 TuiClear+全量绘制+TuiFlush；同属性连续文本一次 TuiPutText（serial 可 grep 整行标记）。状态栏/键位条/选中行用 TuiFill 整行打底。冒烟断言依赖 ConOut 含 serial（S00 已实证）。
4. **冒烟执行目标 = FileManager S00 stub**（`[STUB] FileManager <arch>` 标记）。**S12 合并后 FileManager.efi 变真实应用，标记消失** → smoke/expect-fat-*.txt 与 expect-ntfs-*.txt 需换标记（或 S18 集成时改用专用 target app）。ntfs 场景的 P3 target.efi 是 stub 副本，同理。
5. **S09 语义依赖**：VolFindP3(BootDp,BootLen,&P3Fs) 失败→DEGRADED（不挂死）；VolEnumerate 的 VOLUME_INFO.Dp 用于 Shell 映射名与启动 ESP 匹配（分区 DP 逐字节比较）；FsOps.Info/Open/Read/Close 读 P3 根 launcher.json。glue 保留 Vols 数组至退出（VolFree 收尾），Fs 指针期间有效。
6. **EfiMem**：core/glue 仅用 MemAlloc/MemFree（glue 用 AllocatePool 系）；不依赖 MemRealloc（leader 已修尺寸跟踪，但本流无需用）。
7. 宿主测试复跑：`make -C EasyEfiPkg/Application/Launcher -f host.mk test`（fuzz 种子 0x11A0BEEF 固定）。
8. module.dsc.inc 无需 leader 动作；DSC 聚合已 !include。
