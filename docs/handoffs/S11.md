## 已知限制（设计决策与约定）

1. **core 不依赖 S08 控件**：菜单/确认/帮助/错误页渲染在 core 内（编号/架构灰显/danger 标记/desc 展开属业务语义，TuiWidget 契约明确不管业务）。缩短关键路径；S12/S13 仍可用控件。
2. **core 借用 CONFIG**：glue 持有 ConfigFree/ConfigFreeErrors 生命周期；Reload 回调内 glue 原地更新 LAUNCHER_SESSION。core 不链接 S03 符号 → 宿主测试直接构造 CONFIG 夹具。T11-5 的"坏 JSON"在 core 层以 cfg=NULL+Banner 覆盖；真实 JSON 解析链路由 S03/T03 + 冒烟覆盖。
3. **ExecOps 路径约定（已对齐 S10 实际实现）**：ExecEfi = 活 Fs + 根相对路径（S10 RootRel 只去前导斜杠，不剥 fsN: 前缀）；ExecNsh ShellFullPath = 启动卷根相对、ScriptFullPath = fsN: 全限定（含 ':' 强制）。auto: 候选 FullPath = 根相对反斜杠形式（S10 约定 4），Fs 经 AutoVol 回调解析活卷。
4. auto: 多命中 → CANDIDATES 选择态（Display 展示，options 保留）；单命中直接执行；零命中 → 错误页。
5. boot:XXXX → 直接 ExecBootNext（§5.6 无确认要求）；reset 动作与内置 Reboot → 强制 CONFIRM 默认 N；danger/confirm 标志 → CONFIRM。
6. 数字直选 1-9（单位）；导航端点钳制不环绕、跳过灰显；PgUp/PgDn 按视口行数。>9 条目用方向键。
7. options UTF-8→UCS-2 为 core 内静态严格解码器（非法字节/星面 → '?'；避免跨流依赖 Utf8Lib——集成后可选切换）。
8. `LAUNCHER_CONFIG_MAX_BYTES=65536` 模块常量（建议 PCD 化，见超范围建议）。
9. Count==0（无有效条目）→ 内置菜单 + 横幅（S03 交接约定）。
10. 无 Shell 协议（固件直启）→ 映射名空 → .nsh/fsN: 执行报错页降级；apps 经 BootFs 仍可 exec；菜单/Shell 退出仍可用；EASYEFI_RAN 仅在 Shell 可用时置（§3.4 语义）。ArmVirtQemu 无 SecureBoot 变量 → 状态栏 SB:? 属预期。
11. 倒计时由 glue 驱动（10×100ms PollKey+Stall=1s/Tick，无定时器事件——满足 S10 已知限制 1"调用方自停定时器"，本流无事件可停）；core Tick 纯逻辑可测。skip_timeout 生效值 glue 计算（cfg?cfg->SkipTimeout:PcdSkipTimeoutDefault）。
12. DEGRADED 且配置有效时：菜单=配置项（data: 灰显）+系统项；discovery 行仅在 cfg=NULL 时添加（配置自带 auto: 项即§5.2"auto: 外部介质条目"）。

## 集成注意事项（给 leader）

1. **[阻塞 ntfs 冒烟] 请合并 S10 最终版（stream/S10-execimage e57448b）**：main 上 S10 为接管旧版 14aab7b，缺 fc86913 的 **ExecNsh argv[0] 令牌修复**（Shell ProcessCommandLine 跳过 Argv[0] → 缺令牌则 FileName 不解析 → 嵌套 Shell 重跑 startup.nsh → 无限递归栈耗尽；S10 已 QEMU 双架构实证修复后标记恰好 1 次）。我的 ntfs-aa64 冒烟实测复现该递归（2 次 Synchronous Exception，栈含嵌套 Shell RunScriptFileHandle）。S10 最终版 DoD 已达成（T10 7/7 + 双架构冒烟 PASS + 交接注记），合并后我 rebase 重跑即可，无需改码。
2. **[阻塞 fat/ntfs 干净退出] exec 后池损坏（疑似 S09↔S10 交互，需两流最新版的拥有者排查）**：
   - 现象：fat-aa64，Launcher 经 S10 ExecEfi 执行 FM stub 成功返回后，ESC 退出 → TuiShutdown 清屏后 **ASSERT [DxeCore] Pool.c(721) Head->Signature**（GlueCleanup/Shell SetEnv 期间检测到池头损坏）。ntfs 场景同类损坏表现为 Shell FreeBufferList/RemoveEntryList 崩溃（RestoreBufferList，startup.nsh 收尾）。
   - 二分矩阵（均 aa64，自定义 startup 收尾标记）：A=Launcher 仅 ESC 退出（无 exec）→干净；C=startup 直跑 FM stub（无 Launcher/S10）→干净；G=startup 连跑 FM stub 两次（双 SetEnv）→干净；**B=Launcher+ExecEfi(FM)→池 ASSERT**。→ 损坏源于 S10 ExecEfi 路径与真实 S09 的交互（S10 自身冒烟用 S09 契约替身 UefiVolFixture，未覆盖真实 S09；S09 worktree 另有未提交修改）。
   - 已排除：双重 UnloadImage（edk2 CoreStartImage 经 CoreExit 自动卸载，S10 不再卸载 ✓）；LoadOptions 所有权（DxeCore 不释放注入的 LoadOptions ✓）；S09 FsNormalizePath/PathToUefi/GetInfoAlloc/uInfo 边界 ✓；EfiMem 尺寸跟踪头 ✓；双 SetEnv ✓。
   - 建议：合并 S09/S10 最新后由两流拥有者用 B 场景复现排查（我的 smoke/run-smoke.sh fat 场景即复现器）；重点怀疑 ExecEfi 内部第二次 VolEnumerate+VolFree 与调用方存活 Vols 的交互（S10 交接注记③要求 S09 按卷缓存实例）。
3. **[已报] S09 ExecVolumeLib.inf [Guids] 漏 gEfiPartTypeSystemPartGuid**（VolUefi.c:67 使用）→ 我在 Launcher.inf 临时声明解链接；S09 修复后移除我的临时行。
4. **[已报] S10 ExecAutoCandidates 候选 Fs 悬空**（ExecImage.c:509-512 借用后 VolFree 销毁后端）→ 我的 AutoVol 回调绕开（S10 修复后仍安全）；契约 FsOps.h 建议补 VolFree 所有权注释。
5. **S06 渲染假设**：core 每状态 TuiClear+全量绘制+TuiFlush；同属性连续文本一次 TuiPutText（serial 可 grep 整行标记）。冒烟断言依赖 ConOut 含 serial（S00 已实证）。
