## 已知限制

1. **空输入约定**：Len/Count=0 → `*Out=NULL`、计数 0、EFI_SUCCESS。释放必须走
   `Utf8FreeTokens`（NULL 安全）；**不要对 Decode 结果直接 MemFree**——UEFI `FreePool(NULL)`
   会 ASSERT（DxeCore CoreInternalFreePool 对 NULL 返回 EFI_INVALID_PARAMETER，
   UefiMemoryAllocationLib FreePool 内 ASSERT_EFI_ERROR）。Encode 空结果同理（MemFree(NULL)
   宿主安全、UEFI 危险），消费方判空或统一走包装。
2. Encode 对非法 token（代理区 D800..DFFF、>U+10FFFF、未知 Type）返回 EFI_INVALID_PARAMETER
   且不分配（*Out=NULL/*Len=0）。Decode 输出永不包含此类 token，往返不变量不受影响。
3. 错误路径（参数非法）不分配；OOM 路径返回 EFI_OUT_OF_RESOURCES（未做故障注入测试）。
4. Decode/Encode 均两遍扫描 O(n)、精确分配，**不使用 MemRealloc**（原因见集成注意事项 1）。
5. 无 CHAR16/字符串操作（纯字节逻辑），U16/EfiStr* 纪律天然满足；只 include Contract/Utf8.h + Contract/EfiMem.h。

## 集成注意事项（给 leader）

1. **[ bug 报告 ] S00 EfiMem.c 的 UEFI MemRealloc 实参错位**（leader 独占文件，S01 未触碰）：
   ```c
   VOID *MemRealloc (VOID *Ptr, UINTN NewSize) { return ReallocatePool (Ptr, 0, NewSize); }
   ```
   edk2 签名是 `ReallocatePool (OldSize, NewSize, OldBuffer)`（MdePkg/Include/Library/
   MemoryAllocationLib.h:402 已核实）。现状等价于 AllocateZeroPool(0) 后
   FreePool((VOID*)NewSize) → UEFI 侧崩溃/内存损坏。宿主后端是 realloc，正确，故宿主测试测不出。
   **更深一层**：契约签名 `MemRealloc(Ptr, NewSize)` 缺 OldSize，UEFI 侧无法安全实现
   （ReallocatePool 需要旧尺寸做 CopyMem）——属契约级问题，走 §4 流程裁决（加 OldSize 参数，
   或 leader 侧分配尺寸跟踪）。**S01 已完全避开 MemRealloc，不受影响**；提醒 S02（行数组/
   撤销栈很可能想用 realloc）及其他流在修复前同样避开，或改用 MemAlloc+CopyMem+MemFree。
2. **S02/S13 消费约定**：BOM 解码为普通 CP token（U+FEFF），ModelLoad 用 Utf8HasBom 记元信息、
   token 流原样保留（不剥离）→ 保存往返自动保留 BOM；渲染投影对 Cp>0x7F 的 CP 与全部 RAW
   给 '?' + ATTR_NONASCII，宽度恒 1（Utf8TokenWidth）。
3. 释放配对：Decode 结果 → `Utf8FreeTokens`；Encode 结果 → `MemFree`（非 NULL 时）。
4. module.dsc.inc 无需 leader 改动；DSC 聚合已 !include 本碎片，双架构构建即开即用。
5. 宿主测试复跑：`make -C EasyEfiPkg/Library/Utf8Lib -f host.mk test test-leaks`
   （fuzz 种子固定 0x5EED1234，可复现）。
