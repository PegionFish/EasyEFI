**契约变更提案（待 leader 裁决，未编号）**：

- 动机：`Contract/TuiInput.h` 的 SCAN_* 宏与 MdePkg `Protocol/SimpleTextIn.h` 重名同值。UEFI 构建中 AutoGen.h 强制先引入 `<Uefi.h>`，随后 include 契约头触发 GCC `-Werror` 宏重定义（`0x01` vs `0x0001` 拼写差异），**所有 UEFI 侧消费流都会撞上**。
- 签名 diff：无签名变化；仅建议给 TuiInput.h 的 19 个 SCAN_* 定义加 `#ifndef` 守卫（值与 MdePkg 逐条相同，语义 no-op；宿主侧无 MdePkg，不受影响）。
- 影响流：S07（已用源内 `#undef`  workaround 落地）、S08、S11、S12、S13（UEFI 侧 include TuiInput.h 前需同样处理，见下）。
- 现状 workaround：`TuiInput.c` 与 `Test/TuiInputTest.c` 在 include 契约头前 `#undef` 19 个 MdePkg SCAN_*（SCAN_PGUP/PGDN 为契约独有名，MdePkg 用 SCAN_PAGE_*，无冲突）。

## 已知限制

1. TuiWaitKey/TuiPollKey 仅 UEFI 环境编译（`#ifdef UEFI_BUILD`）；宿主测试只覆盖映射（读键路径由 QEMU 冒烟实证）。
2. 冒烟注入为固定延迟（qmp-keys.py 无标记同步）：首键必须晚于 Shell 启动倒计时——倒计时期间 Shell 每秒 ReadKeyStroke 消费按键（ESC 会跳过 startup.nsh，其它键被丢弃，已读 Shell.c 实证）。aa64 首键 15s、x64 首键 75s，本次双架构实证窗口充足。
3. **aa64 virt 无默认键盘**（QEMU 11.1.3 不自动创建 usb-kbd，`info usb` 实证仅 MSD）→ run-smoke.sh 经 `--extra "-device usb-kbd"` 显式挂载。**x64 q35 自带 ps2-kbd 且为唯一键盘，切勿再加 usb-kbd**（ConSplitter 会把同一 QMP 按键收两份）。
4. 不做 ConIn 复位/按键重复处理（固件职责）；库内无业务分发（契约纪律）。
